# 会话工作进展

顶部栏右侧显示“工作进展”状态，点击后在弹层中查看完整原因和本轮轨迹，不再占用正文上方空间。点击外部或按 Esc 可关闭弹层；暂停动效的选择在收起后保留。新会话显示能力引导；查询、拟稿、制文和知识库处理共用同一展示，不预设后续步骤。用户仍可直接改变需求。

进展由已有运行状态和执行回执派生，不调用模型、不写业务状态，也不新增数据表。Pi 工具协议中的实际调用编号用于关联开始、返回和失败，同名调用及重试不按名称合并。旧记录缺少编号时分别展示观察到的请求与返回，不推定请求已完成。

正文保存、Word 登记、正文确认和知识库写入分别表达。预览准备好只是已发生的工作，是否仍待确认由当前运行状态决定。旧事项文件进入原事项详情，独立文稿进入文档区。收尾答复失败时保留已登记产物，不把模型文字当作文件生成凭证。

只有正在执行的当前轮显示轻微动效；等待启动、停止中、待补、待确认、失败、断线和历史查看均静止。断线优先于任务类型显示“状态待同步”；恢复连接不重放任务或旧动画。暂停动效与停止执行分别处理，并支持系统减弱动效设置。

历史进展明确标记轮次，继续提问先返回当前会话。展开、收起或切换轨迹只操作前端视图，不再调用事项核验接口。已有事项通过“事项记录与审阅”进入原审阅页面，事实、版本和确认保护沿用原机制。

旧流程图、旧焦点栏、节点选择状态、阶段动效映射、图形样式及其专用测试已替换。事项刷新序列和未完成说明的真实业务依赖迁到现有进展模块。旧确认、核验、恢复及历史制文路径仍有调用，继续保留；本次没有删除业务记录。

后端统一输出工具开始、返回和失败回执，不额外记录一份参数或结果正文。历史 `model_tool_failed` 等记录仍可读取；新增调用使用相同编号的 `tool_started`、`tool_returned`、`tool_failed`。接口权限、取消与知识变更确认保持原有约束。

自动检查覆盖轮次隔离、乱序与重复记录、同名调用重试、缺少关联编号、文本与 Word 区分、旧文件入口、部分成功、断线和历史静止，以及原有审批和自动接续。浏览器验收使用隔离数据库和模拟模型；真实模型业务质量、文件内容及人工接受需分别确认。
