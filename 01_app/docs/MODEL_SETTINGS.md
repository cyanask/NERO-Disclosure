# 模型设置与授权

通过网页“模型设置”管理模型、接口地址、启停状态、思考档位和默认路由。默认选择用于下一轮执行，已经开始的轮次保持原模型；失败不会自动换供应商。

## 数据位置

非敏感配置与连接记录保存在 `03_local/var/pi-models.json`、`03_local/var/pi-model-checks.json`，历史配置在 `03_local/var/model-config-history/`。软件示例配置位于 `01_app/config/pi-models.example.json`。

API Key 和 OAuth 凭据由 macOS 钥匙串或 Windows 凭据管理器保存。此次同一工作区内的目录整理保留原项目凭据标识，不复制密钥，也不写系统凭据库。换电脑或复制到其他工作区路径后，应重新授权。

## 使用与控制

在页面添加已获准使用的模型，完成授权后再点击“测试连接”。连接测试会发送短请求，可能消耗账号额度；目录中有模型、凭据存在、连接通过和业务结果通过是不同状态。

供应商及模型目录直接采用 Pi 内置定义，不维护供应商、协议或模型数量白名单。已配置供应商同步后，其返回的全部模型自动加入列表，无需逐个登记确认。现有默认路由和手工设置保留。

## 供应商授权与云端模型同步

API Key 按供应商保存，同一供应商的模型共用一份密钥。旧版单模型密钥在首次同步时迁移为共享凭据；发现多份不同旧密钥时停止迁移，要求重新保存要使用的密钥。移除供应商授权会先写撤销标记，阻止任何遗留密钥回退，重启后仍有效。只有重新保存密钥才能恢复授权。

保存密钥后自动尝试同步，也可点击“同步云端模型”。Pi 提供动态刷新时复用原生刷新；其余按已适配的协议读取云端目录。没有云端目录接口的供应商返回 Pi 原生可用目录，并在数据来源中标记 pi_builtin，不冒充云端账号清单。读取限制为 20 秒、合计 2 MB、5000 个模型、25 页；分页未完成、授权失败或网络异常时保留原配置与上次成功目录。

同步分为读取快照、网络获取和校验写回三个阶段。网络等待在工作线程执行，不持有配置锁；提交前重新核对配置版本、凭据代次及运行状态，期间修改配置、撤销或更新密钥都会使旧结果失效。目录和模型配置在同一次原子写入中保存，默认路由及原有模型设置保持不变。

Pi 内置模型使用原生协议、上下文、输出额度和兼容参数；云端新增 ID 也自动加载。仅返回 ID 的模型采用 Pi coding-agent 的 models.json 加载规则：继承供应商协议和端点，默认文本输入、不声明推理能力、上下文 128000、输出 16384。上述是 Pi 的缺省加载配置，不是对供应商未公布能力的确认。不存在“待确认模型”分支，也不再限制 80 项或把原生模型容量截到 2M／输出截到 8192。

供应商清单保存在 provider_catalogs，后台支持按当前 Pi 重新加载已有清单，不读取密钥或重新查询云端。旧版本的待确认记录在重新加载时自动转为普通模型。模型列表、配置和请求仍保留格式检查与有限体积保护，防止异常响应占满资源；真实鉴权、接口或分页错误会明确返回，不静默截断清单。

执行时通过 Pi 原生授权解析得到请求头和供应商参数，参数仅通过私有管道交给运行器。Cloudflare 账号／网关 ID 可在凭据入口填写并随密钥保存在系统凭据库；原生 stream 负责替换端点占位符和使用专用授权头。Cloudflare 尚无专用云端列表适配时，直接使用 Pi 原生目录。已知模型即使旧配置没有 compat，也会在对应原生端点的运行器内补齐 Pi 原生兼容参数。

页面状态及模型列表查询只读取系统凭据的非敏感元数据，不读取密钥或令牌。macOS 元数据查询显式禁止触发授权界面；只有用户发起同步、连接测试、实际模型执行等需要凭据的操作才读取真实密钥。新保存的凭据同时记录授权类型、撤销状态与参数名称，参数值仍只在受保护的凭据内容中。旧凭据无元数据时只显示记录存在，不据此声称连接通过。

设置操作继续接受本机 Host、Origin 和 CSRF 检查。业务执行期间不允许修改设置或凭据；保存时比较配置版本，旧版本保留。私有凭据不出现在页面返回值、命令参数或普通日志中。

Pi 运行器与依赖位于 `01_app/runtime/pi/`，软件直接复用现有模型协议与授权机制。可选的 OpenCodex / Gemini 通道仍由使用者按原流程准备，本项目迁移不会代为修改全局配置或启动该通道。

## 目录元数据补充

项目内置 Pi 已升级为 0.85.1（官方 npm，MIT）。当前发布目录尚未包含 OpenCode Go 的 DeepSeek V4.1 Flash。运行器按 [Pi 官方模型配置](https://pi.dev/models/opencode-go/deepseek-v4-1-flash) 与 [OpenCode Go 端点表](https://opencode.ai/docs/go/#endpoints) 的明确参数补充精确 ID deepseek-v4.1-flash（2026-09-17 核对），后续 Pi 自带同名模型时自动优先使用原生定义。未把其他相似 ID 猜测为该模型的别名。后端兼容字段名上限可容纳 Pi 的 requiresReasoningContentOnAssistantMessages 等原生长字段。

已配置的 API Key 每个供应商只展示一处“管理授权”入口；输入框、更新和移除操作默认收起。

## 维护约定

模型协议、原生授权、会话重放及上下文压缩的当前接入边界见 [Pi 原生能力接入与会话恢复](PI_NATIVE_INTEGRATION.md)。

### Pi SDK 与完整客户端的接入边界

本项目嵌入 pi-agent-core 与 pi-ai 0.85.1，模型请求仍由 Pi 原生供应商适配器发送。完整 Pi coding-agent 另在上层添加 OpenCode 会话请求头；这些行为并不包含在所嵌入的两个 SDK 中。后端虽然传递了 sessionId，旧请求仍缺少 x-opencode-session。该版本的同类缺陷见 [Pi 上游问题 #9326](https://github.com/earendil-works/pi/issues/9326)，职责分界见 [上游 provider-attribution.ts](https://github.com/earendil-works/pi/blob/main/packages/coding-agent/src/core/provider-attribution.ts)。

统一请求入口现在按当前会话添加 OpenCode Go／Zen 所需的稳定标识，并用 nero-disclosure 标明实际调用客户端。普通执行、工具续轮、节点切换、收尾、独立复核和连接测试均经过该入口；不同会话不共用固定标识。原生协议、授权、模型参数和错误处理仍由现有 Pi 链路承担。升级 Pi 时须核对 SDK 是否已接管该职责，并运行 provider_transport.test.mjs；不能仅凭模型出现在目录中判断接入完整。

2026-09-17 验证：新增测试先复现缺失请求头，再通过实际 Pi 适配器捕获三种协议的 HTTP 请求，检查工具回传、会话隔离及非 OpenCode 请求。50 项 Pi 测试、49 项后端测试通过；当前运行服务的 DeepSeek V4.1 Flash 固定短文本连接测试通过（off 档位，2.07 秒）。此次未重新执行用户的公告任务，连接通过不代表业务结果验收。

前端、后端和 Pi 适配层共同读取软件目录下的 config/model-contract.json。缺省上下文、缺省输出上限、协议名称、推理档位和凭据附加参数在此维护；供应商及模型清单仍由 Pi 与同步结果提供。新建缺省配置采用 128000／16384，已有显式数值不改写。运行器先采用本轮或模型已指定的输出上限，再使用共享缺省值。

模型目录转为前端配置的字段映射统一由 profileFromCatalog 处理；Pi 会话初始化统一由 providerSession 处理。凭据状态查询与真实密钥读取保持分离。macOS 软件复制清单包含共享配置，避免源码运行正常而安装包缺文件。

## 原生默认规则依据

新增模型的缺省加载规则来自 Pi 0.85.1 的 packages/coding-agent/dist/core/provider-composer.js（modelFromJson 与 findModelDefaults），文档见 https://github.com/earendil-works/pi/blob/main/packages/coding-agent/docs/models.md 。云端列表适配只补齐 Pi 当前尚未实现的供应商清单获取，不另设人工批准流程。依赖安装禁用 lifecycle scripts，运行器沿用 Pi 默认的空遥测上下文。
