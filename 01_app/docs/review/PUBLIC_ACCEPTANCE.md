## 本次发现并修正的上传配套问题

| 问题 | 修正与检查 |
| --- | --- |
| 新增开发入口每次启动都会把样例复制覆盖到既有开发库 | 改为首次完整初始化、再次启动原样保留；无有效标记、链接目录或部分初始化不静默覆盖。新增保存修改与拒绝覆盖的回归测试 |
| 空开发环境只有公司登记入口，需要模型联网才能进入工作台 | 仅开发入口预置 `000000 / 虚构审查公司（仅开发）`，不伪造官方身份核实或生产确认 |

| CI 没有执行已有前端行为测试 | 增加 `npm test`；保留类型检查与构建，两者不能替代行为回归 |
| 缺少审阅入口和完整性依据 | 增加功能/源码/测试表、状态与权威说明、成熟度缺口、120 项接口索引及397项来源对照 |
| 公开资料防回流与文档口径不足 | 扩展忽略规则；CI 检查跟踪文件中的资料目录、数据库、凭据文件、本机路径及常见令牌形式；修正 Node 最低版本、前端构建责任和开发数据路径说明 |

## 仍需同事评审的工程问题

1. 正式知识包的版本期望、全文覆盖与专业规则测试，不能由虚构样例替代。
2. 真供应商的延迟、成本、长运行取消/重试、结构化输出和业务质量，缺少系统化评测证据。
3. `PiRuntime` 兼管多种意图、工具与恢复状态，旧工作流和新文稿流程并存，维护成本需针对实际变更评估。
4. 系统是本机单用户工作台，Host/Origin/CSRF不提供多用户鉴权；没有分布式可用性、负载、恢复时间目标或生产 SLA 证据。
5. Python依赖无逐包哈希、缺完整 SBOM/漏洞扫描基线；CI有 Actions Node 20 弃用提示和前端大资源包提示。
6. Windows/Intel Mac 实机、签名公证、安装更新与卸载、备份恢复演练及 Word 版式人工接受须另测；构建脚本存在不等于这些工作已完成。
7. 分支保护尚未启用，本次没有改动仓库贡献者权限。公开可见仅解决同事与外部评审者访问源码的问题。
