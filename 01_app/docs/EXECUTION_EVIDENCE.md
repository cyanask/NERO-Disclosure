# 执行记录：会话依据清单

执行记录默认按当前公司、会话展示五类来源：法律法规、案例库、黑名单库、历史公告、模板。打开会话后可切换整个会话或某一轮；对话内的入口默认显示当前轮。

资料名称和条号来自当次记录，重复读取按资料编号和版本合并。同一法规的同版本条号在前台合并展示。检索结果和提供给模型的上下文单独折叠；成功读取、结果引用、模板匹配和实际采用分别标记。引用记录不等于专业核验通过。

历史公告的“全部”只指当次快照内本公司的全部已登记公告。现有自动检查只比较公告编号、会议日期，前台明确显示比较字段及份数。单页或全文读取只登记查阅范围，不自动升级为全文核对通过。未连接、未命中、失败和缺少完成回执分别显示。

系统治理新增“技术记录”和“事项办理记录”入口，保留原始日志、事项状态、待补问题和人工处理能力。业务门禁未改变。

## 实现边界

- `evidence_access.py`：对已登记的工具成功/失败结果追加精简回执，复用原有 journal，不改数据库结构。
- `evidence_summary.py`：只读汇总；SQL 排除用户消息、助手全文和流式文字，保留全部相关回执，不受原日志接口每页 1,000 条的限制。
- `evidence_api.py`：复用浏览器身份检查和公司归属解析；会话摘要必须同时指定公司和板块，单轮须属于该会话。
- `announcement_history.py`、`gates.py`：现有编号/会议日期检查增加范围回执，不新增专业结论。
- `ExecutionEvidence.tsx`：会话列表、五类清单、轮次切换及加载/错误状态；完整技术日志沿用原组件。

旧记录仅使用原有成功返回、上下文和结果快照还原；无法还原的操作不补写成功。新增回执不会回填旧日志，也不重新调用模型。

只有发起动作的记录，前台直接显示具体操作，例如“已发起查询历史公告库的可检索范围、数量及目录”，或“已发起查询法规库：关联交易”。同样适用于五类资料；不以“记录不足”代替动作描述。已有成功或失败回执的请求不再重复显示为仅发起。

## 验证

后台专项目录测试覆盖查阅与检索区分、重复读取、版本隔离、失败/无命中、旧公告回执缺失、单页范围、模板匹配与采用、超过 1,000 条日志、公司/板块/轮次隔离及归档筛选。配套运行会话、资料复用、Pi 执行和公告工作台回归。

前端测试覆盖五类信息、条号合并、版本区分、同名案例的证券代码、失败提示和来源链接安全。

2026-09-16 本次验证：50 项后台回归通过；防御性参数处理补充后，10 项专项测试再次通过；12 组前端测试、TypeScript 检查和网页资源编译通过。已在本机 8765 工作台、1280×720 桌面窗口，以现有公司会话验证会话列表、五类清单、单轮隔离、对话内入口、技术记录入口及上下滚动，浏览器未记录页面错误。

验证未新增真实模型调用，也不代表法规适用或业务结论获人工认可。历史来源名称保持原记录；抽查中一条案例旧标题带有“隔离测试”字样，本次未修改该知识资料或原回执。
