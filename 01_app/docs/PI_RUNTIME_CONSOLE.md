## 进入操作台

1. 启动本项目，选择创业板，进入“对话操作台”。基础层和创新层已归档，不属于当前运行面。
2. 新建会话，绑定已有事项，或登记一个新事项。绑定后的公司、板块与事项不随模型变化。
3. 选择本轮模型，直接说明需求。Pi 先分流至咨询、拟写公告、Word 制作或知识库操作；节点执行读取对应 Skill、冻结依据，并按当前合同提交候选。
4. 上部流程根据事项状态及 Pi 回执变化。普通披露核验通过后自动继续；不披露、暂缓或特殊方向仍须实际人工决定。文本路线在完整正文人工确认后结束；需要 Word 时直接提出制作要求；runtime 基于当前内容出稿，用户在文档卡片中集中审阅。
5. 在“执行记录”中查看每轮全过程。原有事项版本、节点任务及人工确认记录继续保留。

模型运行时可以停止。停止不会撤销此前已经完成的工具动作，相关候选和文件保留在记录中。会话可重命名、按名称检索、归档与恢复；归档保留完整记录。

确认后的自动接续若仍在排队，页面提供“暂停自动接续”。暂停请求后重新读取真实状态，保留已保存的正文确认；它不撤销已经完成的动作。运行中的模型仍使用“停止执行”。

资料不足时，在“补充或修订事实”中更新事项，或通过模板节点补充规划中已列明的制稿资料。更新关键事实后，原有版本校验会使受影响候选与确认失效。人工升级及节点回退继续使用事项记录中的恢复入口。

旧流程的正文确认与其当时文件及依赖绑定，保留历史含义，不补写批准。按需制文使用独立文稿快照，用户最终审阅当前文件；不修改旧事项进度。

“模型设置”支持添加 Pi 内置模型或填写已核实的模型 ID、启停与显示、推理档位、节点默认路由、账户授权及连接测试。可用性以当前授权和实际连接结果为准。

进入设置页后，点击 Luna 的“登录 ChatGPT”，由 Pi 发起 OpenAI 设备授权；用户在 OpenAI 页面自行登录和确认。授权保存在本项目专用系统凭据库。也可为其他已批准接口在网页填写 API Key；不要把密钥发到聊天或写进模型 JSON。

“重读 Pi 目录”重新读取当前安装版本的目录快照，显示其生成日期，不会自动升级 Pi 或承诺在线最新型号。“测试连接”只发出固定短请求，不携带事项、底稿、聊天历史或工具；可能消耗账户额度。连接结果与配置指纹绑定，修改配置后须重新测试。

| 配置 | 用途 |
| --- | --- |
| 模型名称、供应商、ID、协议和地址 | 确定实际请求目标；OAuth 固定为 OpenAI ChatGPT 端点 |
| 授权方式 | 本项目 ChatGPT 登录、API Key 系统凭据库、专用环境变量或本机接口 |
| 推理档位 | 依已核实的支持范围传给 Pi；内置模型保留原目录的档位映射 |
| 上下文与输出上限 | 作为本轮配置传给 Pi；实际约束仍取决于接口支持 |
| 启用与显示 | 控制能否选择，以及是否在对话栏展示 |
| 默认路由 | 所有节点默认及六类工作的默认模型，发送前仍可手动选择 |

非敏感设置保存到当前数据目录的 `pi-models.json`，默认是 `var/pi-models.json`；保存采用版本校验和原子替换，旧版本留在 `model-config-history/`。旧的 `DISCLOSURE_` 专用环境变量方式继续兼容，示例见 `config/pi-models.example.json`。进程不会读到其他终端后来设置的变量。

每轮固定业务模型、接口、推理档位及上下文哈希；失败时不自动改用其他供应商。分流使用同一模型的独立预算，优先选择受支持的 low 档，输出上限为配置上限与 2048 Token 中较小者；不支持 low 时使用已支持档位。进入业务节点和收尾后恢复所选档位及输出上限。

执行记录展示选择与 Pi 返回标识，不证明远端内部的物理模型路由。用量按 Pi 返回 Token 留存，缺少价格时不推算费用。分流预算降低不等于整轮费用或 Token 已减少，也不替代正文和 Word 的实际人工确认。

完整状态、验证范围、平台限制和恢复方法见 [模型设置与 Luna 接入](MODEL_SETTINGS.md)。

| 对象 | 本次记录 | 如何判断 |
| --- | --- | --- |
| 对话 | 用户文本、助手可见文本、流式片段、起止状态 | 不记录模型私有推理；结束消息不能改变事项状态 |
| 模型 | 本轮选择、进程句柄、Pi 启动与结束回执 | 收到请求、建立进程、真正开始、完整结束分别记录 |
| 耗时 | 分流、业务模型、工具、收尾模型、资源清理及总耗时 | 各项按运行回执记录；不把总等待时间全部归于模型生成，也不将分项重复相加 |
| Skill | 节点、版本、文件及引用哈希、上下文哈希 | 本地装载与 Pi 注入分别记录；结果还须符合合同并通过 Gate |
| 知识库 | 查询参数、事项与板块绑定、返回内容 | 目前使用 `in_process_harness`，不标作 MCP；客户历史和内部材料未连接时如实返回 |
| 候选 | 提交、载入、核验与流转的独立回执 | 继续使用原有任务租约、指纹及 Verify/Gate |
| Word | 登记脚本路径、脚本哈希、运行结果、文件哈希、登记结果 | 实际生成并登记后才显示文件；逐页视觉与内容接受仍待人工 |
| 人工确认 | 现有事项确认记录与当前版本 | Agent 不能调用确认接口；产品确认不证明法定权限或公开发布 |

当前运行记录已增加中断模型调用耗时，`cleanup_ms` 也包含 Python 回收子进程的耗时。上述双模型全稿复测使用修订前口径：模型分项仅含已结束调用，清理分项不含 Python 停止等待，因而与总时长存在差额。该限制只属于那一轮记录；详表见最终验证记录（本机历史记录，未随源码仓库分发）。

普通咨询加载项目级 disclosure-consultation Skill。拟公告和 Word 需求都先执行[起草行为合同](specs/DRAFTING_BEHAVIOR_CONTRACT.md)：分流仅选择目标，assess_document_readiness 登记文稿范围、核对主题及分类缺口；存在未告知的正文内容缺口时先提醒并等待用户选择，之后才开放 save_announcement 或 make_word。用户接受同一缺口后可制作待补草稿，不重复要求补齐；缺口接受与正文确认、文件定稿及发布分开。旧事项的内容要求作为核对基准复用，不强迫重跑全部节点。来源定位问题先由主控修正；跨会话访问、版本冲突和原稿保护继续有效。

当前 Pi 未连接 MCP 服务，知识库调用通过同一进程中的已登记 Harness 路由完成。外部宿主 HTTP、CLI 及 MCP 接入链已移除，Pi 直接调用进程内工作流；历史记录仍保留。公开搜索、官方资料读取和知识库维护沿用已登记工具及权限边界；检索命中不自动接纳为正式依据。

会话文档卡片仅保留“文字预览”和“下载 Word”，使用统一按钮样式；修改要求直接在对话框输入。交付文件页同时展示本公司的会话 Word 和旧事项交付记录：会话文件直接读取已有版本登记，每份文稿展示最新 Word，不重复生成、复制或推进事项状态。纯文本草稿不计入 Word 清单；归档会话的文件仍可下载，缺失或被改写的文件显示不可用。历史版本仍保留在原会话中。

本地检索保留精确结果优先；精确为空时支持短词、标点拆词及条款定位，部分匹配返回未匹配词和覆盖限制。`view=groups` 用于分组定位。本轮同一资料版本和参数的读取结果可复用，版本变化即清空缓存；缓存命中不算新增证据。连续三次搜索没有新增资料后，仅提示调整策略，真实结果仍返回，后续查询不被拦截。条文定义、例外、有效期和原件仍须核对。

## 留存与恢复

会话、轮次和回执存入独立的 `var/conversations.sqlite3`，不把聊天全文写入披露事项版本。事项与审批仍使用 `var/disclosure.sqlite3`。本次没有迁移或删除原事项数据库。

同一事项同时只允许一个 Pi 轮次执行。重复发送同一逻辑请求返回原运行编号；不同内容复用编号会拒绝。运行状态采用 `accepted → running → completed / waiting_user / waiting_approval / blocked / failed / cancelled / incomplete`；重启发现上轮未结束时标为 `interrupted`，不自动重放写入。

单轮不设固定时间上限，资料调用次数及由资料调用产生的模型轮数均不设数量上限；用户可随时停止，输出大小、模型接口自身限制、资源清理及节点提交纠偏次数仍受运行边界约束。未取得结果则标记未完成，保留公开文字为“未完成说明”。模型说“完成”不等于节点已登记并通过核验。

分流与咨询保留近期公开消息。同一节点修订时只保留最新未通过候选和错误；进入新节点后从服务端的当前事实、依据及版本重新开始，不搬运全部历史工具回执。完整历史继续留在执行记录，不作为下一节点的重复输入。

运行记录会隐藏已知凭据和二进制正文；模板与 Word 文件另行留存。不要在聊天中输入凭据。运行时通过标准输入向本轮子进程传入专用凭据，不使用命令行参数或日志传递。工作进程先执行会话资源清理，再发出 `done` 回执；清理失败不能发出成功结束回执。父进程另行回收未结束任务并记录清理耗时，保留已登记业务结果；停止或连接中断不重放写入。

2026-09-13 的真实 GPT-5.6 Luna · max 正常结束复验状态为 `completed`：同模型 low 档分流 3.817 秒，max 档咨询回答 4.080 秒，总计 8.007 秒；清理约 0.003 秒，`done` 至 `settled` 约 0.004 秒。回执显示 `remaining_sockets=0`，进程自然退出，未触发 `cleanup_fallback`。这证明该次正常结束未额外保活五分钟，不证明正式业务全稿通过；双模型全稿超时结果不变。
