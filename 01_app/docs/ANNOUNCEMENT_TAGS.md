# 公告时间表标签

沿用公司目录、页级正文、公司 SQLite 索引和现有 Pi Runtime。历史公告的唯一页面入口为“公告时间表”。

当前策略 `announcement-tags-v2-pi-review`：本地规则未达到有校准证据的99%门槛时，必须进入Pi复判。现有规则没有独立统计校准，因此其输出全部是候选，`rule_confidence=null`，不可伪写0.99。有效人工校正优先；同一原文版本已有Pi复判结果时直接复用。点击标签及GET查询不触发模型调用。

Web新增历史公告完成入库后自动发起复判；对话入库沿用原会话所选模型；Web和官方批量下载沿用模型设置中的默认模型。批量下载将确切文件及版本交给本机8765服务，服务未运行或未授权时明确记为待Pi识别。存量待识别文件或失败任务可在公告时间表点击“Pi复判待识别”重新发起。系统不会自动改用其他模型。

复判使用原有`PiRuntime.accept/work/process`和`runtime/pi/worker.mjs`，每批6份，未完成批次在同一分类会话中自动接续。这个分批只控制上下文规模，不限制资料读取次数。单轮没有固定时间上限，用户可随时暂停；输出、模型接口、资源清理和有限纠偏边界继续生效。运行、耗时、模型及结果保存在原会话执行记录中。停止、失败或中断后，未完成文件仍为候选，须重试；不会伪装成复判成功。

Pi只可读取本批公告页和提交分类，不能调用其他知识维护或披露制作工具。结果必须使用既定标签，并附原文页码、逐字摘录和判断理由；服务端验证公司、文件版本、引用、标签范围及人工校正保护后保存`classification_review`。Pi无法确定时标记待人工识别。模型自报置信度不作为99%校准证据。

复判层验证：分类、工作台和Pi运行时组合测试54项通过，新增Web入库自动发起复判用例1项通过。本机曾以默认模型经现有 Pi worker 完成一份公告的真实复判，分类为审计／持续督导，细分为其他文件，附当页逐字摘录与理由；界面已核对“Pi已复判”及依据页。仅这一份完成真实模型验证，其他存量规则标签仍是待Pi复判候选；不把整库宣称为已经完成模型识别或人工验收。

- 常用：股东会、董事会、年报、半年报、季报、分红派息、募集资金。
- 更多：业绩预告／快报、股份变动、回购／股权激励、关联交易、对外担保、投资／资产交易、理财／套期保值、人员／公司治理、首次发行上市、再融资、风险／监管、投资者关系、审计／持续督导、待分类。
- 细分：通知、决议、法律意见书、报告全文、报告摘要、更正／修订、配套文件、其他文件。

标题和文件性质优先。股东会兼容旧称股东大会；议事规则、章程、管理制度及董事会工作报告不计作会议。年报只收报告全文、摘要及其更正；审计和其他配套报告在审计／持续督导标签中查询。IPO 与再融资分开。规则适用多标签，例如募集资金核查意见可同时属于募集资金和持续督导。

本地规则只有在“附件”等无信息标题时才使用页首标题候选。Pi复判获得每份首页，并可继续逐页读取原文，判断文件用途。自动分类是文件导航，不代表专业核验已经完成；候选标签在页面明确标为待Pi复判。

`backend/announcement_tags.py` 为版本化规则。建索引时将分类、依据和版本写入同一个 SQLite 的 `classifications` 表；所有入库、删除、恢复和校正沿用既有索引重建流程。目录或原件／正文变化及规则升级使旧投影过期。原件、正文和目录仍是真源。

人工校正保存在目录的 `classification_override`，经原有 Web 用户权限、目录指纹和原因校验后记录历史；绑定标题、正文和原件哈希。正文版本改变后旧校正失效，可重新校正；“恢复自动分类”只移除本条人工覆盖。删除记录默认不参与分类数量。

`GET /api/announcement-schedule` 增加 `tag` 和 `form`；与 `q` 全文检索取交集。一次选择一个主题，可再选择一种文件细分。标签数字为当前公司、删除开关及搜索词范围内的文件数；同一文件可进入多个主题，计数不可相加作为文件总数。分页每页20条，改变筛选回到第一页。关联公告选项来自全公司有效目录，不受标签筛选影响。

规则及公司隔离、全文查询、人工覆盖、版本失效、删除恢复有回归用例：`tests/test_announcement_tags.py`、`tests/test_announcement_workspace.py`。真实公司分类还需人工验收。

2026-09-14 实施验证：上述31项测试通过；前端类型检查及生产构建通过。该示例公司的全部有效文件均生成自动分类，目录 SHA-256 在本轮前后相同，原件和正文完整性检查通过；页级与大文件二级索引完整。索引重建前的旧副本由作者保存在本机历史区，不随源码仓库分发。

实际本机页面在1440×1000、1920×1080桌面窗口检查标签、细分、更多标签、空搜索及恢复、键盘标签操作和校正窗口；没有在真实公司数据上保存测试校正。筛选条目数与接口一致。人工校正的保存、目录历史和失效行为在隔离测试数据上验证。截图位于 `output/playwright/announcement-tags/`，最终可见校正窗口为 `correction-final.png`，年报页面为 `annual-1920.png`。自动归类不等于173份文件已经逐份完成专业验收。
