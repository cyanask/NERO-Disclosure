# 模型配置

在工作台的“模型设置”中添加供应商、完成授权、启用模型，并选择默认路由。会话开始后保持本轮已选模型，调用失败不会自动切换供应商。

## 首次配置

1. 选择供应商和账号提供的模型；兼容接口需填写实际 API 类型和端点。
2. 保存 API Key，或按照页面提供的 OAuth 流程登录。
3. 同步模型目录，启用需要的模型，然后测试连接。
4. 在对话操作台选择模型并发送需求。

连接测试和实际执行会调用对应服务，使用自己的账号额度。目录存在、授权存在、连接可用与业务结果正确需要分别判断。

## 配置与凭据位置

| 内容 | 位置 |
| --- | --- |
| 示例配置 | [config/pi-models.example.json](../config/pi-models.example.json) |
| 协议、推理档位等共享定义 | [config/model-contract.json](../config/model-contract.json) |
| 当前模型与路由 | 当前数据库目录中的 `pi-models.json` |
| 配置历史与连接结果 | 同目录的 `model-config-history/`、`pi-model-checks.json` |
| API Key 与 OAuth 令牌 | macOS 钥匙串或 Windows 凭据管理器 |

开发入口的数据库目录为 `03_local/dev/var`，常规源码入口为 `03_local/var`。示例配置不会自动授予模型访问权；换电脑或工作区后应重新授权。

## 供应商与同步

供应商目录及模型协议以安装的 Pi SDK 为基础。API Key 按供应商保存；移除授权后，旧凭据不能作为回退来源。同步失败保留上次配置，不写入部分目录。没有云端目录接口时，界面标明使用 Pi 内置目录。

AWS、Vertex、Azure、Cloudflare 等供应商的附加参数仅接受已有适配支持的字段。可选 OpenCodex/Gemini 通道需自行准备对应服务，本项目不会代为安装或启动全局服务。

业务运行期间修改设置可能被拒绝；先停止或等待该轮结束再保存。配置版本发生冲突时重新读取，不覆盖其他已保存的修改。

## 排查

| 现象 | 检查 |
| --- | --- |
| 没有可选模型 | 模型是否启用、是否在聊天栏显示、默认路由是否设置 |
| 授权存在但调用失败 | API 类型、端点、模型 ID、账号额度与服务错误信息 |
| 同步失败 | 网络、授权有效性、目录接口和分页结果 |
| 运行组件未安装 | 在 `01_app/runtime/pi` 执行 `npm ci`，确认 Node.js 可用 |
| 切换路径后要求授权 | 为该工作区重新授权，不复制其他工作区的凭据 |
