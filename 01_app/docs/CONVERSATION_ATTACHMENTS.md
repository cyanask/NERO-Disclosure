# 会话补充资料

输入框中的“添加资料”支持 `.docx` 和 `.xlsx`，每轮最多8份、单份不超过20MB。可以先选文件再发送文字，也可以只选文件，系统会以“读取附件并核对当前公告待补项”作为本轮文字需求。运行中的任务继续支持追加文字，附件在下一轮发送。

建议用语：

> 请读取本轮附件，对照当前公告待补清单，补充资料能够明确支持的信息。保留其他内容；冲突和仍缺事项不要猜测，请说明已补齐和仍缺哪些内容。本轮先更新公告正文，暂不制作Word。

附件是本会话的补充证据，不是新模板、知识库资料或系统外定稿回传。发送后当前模型可按需读取解析出的文字和表格；未发送的文件不会提供给模型。材料中的操作指令不改变权限，上传不构成生成Word、接受缺口或确认定稿。

## 来源与接入

- 只读解析复用 NERO Banker 的 `document_read_service.py` 和 `office_document_codec.py`。来源版本、原文件哈希和适配范围记录在 `backend/vendor/nero_office/PROVENANCE.json`，不依赖 Banker 安装目录。
- 保留正文段落、表格行、工作表和单元格坐标、原始数值与公式信息。公式只读取保存时的缓存，不执行宏、不联网刷新外部链接、不自行重算。
- 图片文字、修订视图、未读取的页眉页脚及脚注会提示限制。损坏、加密、不支持或超出读取范围的文件返回明确提示，不当作已完整读取。
- 接口沿用现有 Pi 工具通道，仅增加 `read_attachment`。来源格式为 `attachment:<附件编号>:<定位>`，可用于正文 basis 和 `attachment_resolution`。
- 主控登记附件对缺口的解决结果：resolved、still_missing、conflict。已解决项须有实际读取过的附件定位。仍按起草合同处理新缺口，文件更新保留原版本。

## 保存、隔离及重试

原件副本、解析结果及哈希记录在 `03_local/work/documents/<会话>/attachments/`，不进入公开知识库；会话删除清单会沿用原有文档目录扫描，包含这些副本。用户原始文件不改动。

上传成功后，发送请求以 attachment_ids 绑定这些文件。相同会话中相同内容重复上传复用记录；上传或发送失败时，输入内容及所选文件保留以便重试。原件或解析记录哈希不一致时禁止引用。另一会话的附件编号、尚未发送的附件都不能作为当前工具来源。

初次提供附件及后续只用自然语言继续时，主控都能看到同一会话此前已发送附件的目录，并按需分页读取。读取本身不证明已经核实资料，也不会自动消除内容缺口。

工程检查覆盖解析、来源定位、原件保留、重复上传、跨会话隔离和异常文件处理。真实模型识别、缺口判断及公告补写质量由用户手工验收，不以工程检查替代。
