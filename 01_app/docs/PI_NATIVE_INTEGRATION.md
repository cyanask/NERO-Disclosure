# Pi 原生能力接入与会话恢复

本轮修复统一了“配置允许什么、运行时执行什么”，并接入当前 Pi 0.85.1 SDK 已提供的会话消息队列及上下文压缩能力。未新增依赖，未更改人工确认、事项权限或证据口径。

## 模型与授权

配置声明的 API 决定实际请求协议。原生供应商支持该 API 时沿用供应商适配器；明确覆盖协议时，转用 Pi 对应 API 实现。共享配置中的十种 API 均有可加载的原生实现。

合法的兼容参数表达式和非推理模型的 off/null 映射可以保存。目录中的 Azure 模型允许先保存空端点，但填写实际端点或资源名称前不显示为可用。云端同步仍先完整校验，再一次性写入；失败不会留下半份目录。

OAuth 登录方式取自已安装 Pi 的供应商目录，复用其设备码、授权链接、交互选择及验证码流程。输入只通过本机私有管道传给 Pi；令牌仅保存到系统凭据库，页面状态和普通日志不包含令牌。取消、步骤过期以及登录期间更改供应商均有独立处理。长轮次在每次模型请求前重新解析所选模型的 OAuth，刷新结果仍由原凭据库保存。

AWS、Vertex 和 Azure 参数按供应商白名单保存到凭据库，随本次选定授权传递，不导入整个宿主环境。AWS 可以使用指定 Profile 或明确填写的 IAM 凭据；Vertex 可以使用 API Key，或明确指定的凭据文件、项目与地区；Azure 可以填写资源名称、端点及部署映射。配置完整与实际连接通过是两个状态。OAuth 目录遵循 Pi 原生可用模型过滤，不冒充 API Key 的云端列表接口。

## 会话与上下文

新轮次从对应会话的运行记录恢复 user、assistant 和 toolResult 等原生消息角色，不再把助手回答改写为用户指令，也不再固定只保留最近二十条消息。旧轮次没有可重放工具记录时，仅恢复实际存在的公开消息，不补造历史工具结果。

重放文件位于当前数据目录的 pi-runs/运行编号/context-state.json，使用临时文件与原子替换保存，文件权限为 0600。私有思考块不写入重放文件，已知凭据值会脱敏。每份文件绑定会话及运行编号；文件损坏或绑定不一致时明确报错，不静默丢弃历史。该目录已经纳入现有会话删除预览与备份清理范围。

接近模型上下文容量时，使用 Pi 原生 prepareCompaction、compact 和消息转换逻辑。系统事实、工具范围及审批状态保留在当前系统上下文中；历史摘要不能替代这些现行信息。压缩前的可重放原始记录另存于同一运行目录。摘要使用独立会话标识、同一选定模型及授权，不执行业务工具；摘要失败、截断或压缩后仍超限时，保留原记录并停止。用户配置的输出上限同样约束摘要请求。

执行中可选择“当前工具结束后追加”或“当前工作结束后处理”，分别接入 Pi 的 steer 和 followUp。请求编号用于防重，页面区分排队、已接收和未执行。独立核验不接收中途指令；本轮进入人工确认、收尾或取消边界后，未处理消息明确提示重新发送，不据此自动重跑业务。

## 验证与恢复边界

覆盖检查包括：当前完整模型目录的配置加载、真实 Pi 协议序列化、供应商参数隔离、OAuth 交互与过期步骤、私有重放、摘要失败保护、追加消息及业务门禁。另用隔离数据和本机模拟供应商验证真实 Python → Pi 子进程 → HTTP 请求 → 跨轮恢复链路。

真实供应商连接只使用固定短文本；未以合成测试替代各供应商账号的实际登录，也未自动重跑用户的公告任务。页面效果验收和用户人工接受须分别记录，不由代码测试推定。

代码可通过本次本地提交回退；运行前已有业务记录和模型配置未做批量改写。需要诊断重放问题时，先保留对应运行目录及其压缩前副本，再核对会话和运行编号。不要直接删除整个 pi-runs 目录；正式删除继续使用系统的会话范围预览与确认流程。
