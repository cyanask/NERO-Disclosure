# 公共知识库全文索引

日期：2026-09-16。当前公共知识库只开放创业板，以 `data/public/boards/chinext/` 下的 `catalog.json`、页级正文和官方原件为真源；`disclosure_library.sqlite3` 是可重建检索投影。基础层和创新层的同类资料已外部归档，入库、编辑和删除仍沿用现有同步入口，不增加第二个控制器。

法规库FTS只索引规范条目的法规名称、条款编号、现行条文、生效/失效时间、板块及事项适用信息。原始PDF页不作为法律权威正文；Agent取得候选后仍按条款编号和适用时间读取当前规范条目。

页面呈现采用两级结构：法规库先查询 `view=groups` 展示每部法律／法规及条款数量；点击目录项后通过现有条目读取接口返回该法规的条款列表，再按条款读取正文。法规目录和条款共用同一份 `catalog.json`、SQLite FTS 与版本指纹，不复制原件。

案例库将全部条目写入一级目录，并为存在提取正文的资料建立页、章节、段落或表格单元和中文FTS。查询按 `admitted` 字段强制区分已核实案例与待核资料；待核命中只能出现在待核视图，不能进入正式案例结果。章节路径是规则推导，页码、页内锚点和原文摘录用于复核。

黑名单案例库按一项信息披露违规事项建立一条案例记录，不按文件份数重复计数。每案关联官方处理决定、涉事公告、更正、整改或后续文件；监管认定、系统摘要和起草检查项分别保存。只有官方处理决定及违规时点板块均已核实的事项进入已核实视图，问询、立案和自行更正只进入待核视图。处理性质区分行政处罚、交易所纪律处分和监管措施，历史处理依据不能替代当前法规核对。

索引保存法规、普通案例、黑名单案例目录和资产版本指纹。黑名单全文索引按“事项—证据文件—页码—章节路径—段落锚点”返回结果。目录或正文文件变化后，运行时拒绝将旧索引标为当前，继续使用JSON真源；正常知识库写入会原子重建SQLite。索引覆盖或已核实案例原件校验失败时，新SQLite不替换旧版本。

代表性检查确认：创业板普通案例查询可以命中目录2,000字之外的正文；“汽车分销渠道”仅在待核视图返回；法规“信息披露义务人”“第五条”通过法规FTS返回当前条款。黑名单查询“销售返利”定位长方集团处理决定及页内原文，公告类型、错误类型、处理性质和年份筛选分别生效。板块迁移前的三板块索引记录仍保留在外部归档；当前只以创业板索引作为运行面，相关公共接口、索引和维护检查与本次迁移后的验证结果分开看待。

技术通过不表示案例适用性或法律结论已经人工确认。Agent只通过现有知识库服务读取，不能直接写SQLite。
