# 披露范围与颗粒度

本Skill由plan任务绑定。读取冻结的第一节点确认、事实、profile、案例和结果schema；上游 Gate 未通过或任务已失效时不能继续编制候选。

先核对profile适用情形。一般关联交易若涉及资产买卖、投资、理财、担保、日常预计或重组，应核对专项文种；任命、辞任与换届，首次通知、延期与新增临时提案分别判断。默认文种只是有限匹配，不能替代业务判断。发现文种不合适，明确所需调整，更新事项文种后重建任务，不提交与冻结profile不一致的清单。

规范要求以本次适用法源和官方格式为依据。实践颗粒度以官方案例原件及指定页为依据。比较事项性质、层级证据、时间、规模、角色、程序阶段及特殊情形。已登记案例的发布时层级可能未知；补发、更正和累计公告应单独说明角色。非关联理财案例只作结构对照，不能据此认定关联交易要求已经满足。扫描转录和机器表格文本不足时查看原件，不推断列关系。

逐项保留profile或已有清单中的必备项目ID，区分必填、条件适用和可选内容。每行填写requirement、detail、evidence_status、source_ids、notes。detail应是拟披露事实或明确待补内容；条件项不适用时写明事实和依据，不能删掉项目。格式规则规定“如适用”的，不能因案例包含就一概设为必填。

source_ids区分法源与已登记原件案例；notes说明案例出处、具体页码、可比点和差异，清楚标明哪些要求来自法规、哪些只是案例实践。案例中的金额、票数、人物、履职程序及结论不得移植。本节点形成可供审稿的清单，不把“按规定披露”等空泛语句当作颗粒度已明确。

缺少原始事实、审计口径、定价资料或程序证据时保留待补及所需材料。不要把“公允”“无影响”“程序合法”当作默认值。清单中的待补项会阻断载入和推进；需先补齐本事项事实和证据。

## Verify/Gate 与缺失法源

先读取 verification_gate 或调用 verify.run。法规库（R1）提供权威法源；案例库、文种 profile 与版式规则（R2）约束生产。法规时效不符直接停止推进，回法规库读完整条文、核对适用期间与核验截止日期。库中缺失时由当前外部 Agent 使用自己的互联网检索工具查官方原文；不得把候选片段或案例当法源。

检索到适用版本后，先用 library.manage/update 收录法规库（含官方 URL、正文、生效/失效日期、核验日期；替代版本须新 id 并登记 replaces_source_ids），必要时 law.bind 绑定本事项版本，再重建任务。检索不到或宿主无法联网时，调用 source.search_report，填写本节点 stage、verify.run 的 input_fingerprint、实际查询、原文地址和原因，反馈用户并停止后续节点。found 只记录线索，不会放开 Gate；not_found 不得继续生产。

通过 task.submit 留存候选，task.adopt 在当前版本 Verify 通过后才载入；gate.advance 再核对事实、法源及上游依赖。Web 与 Agent 使用同一 Gate，均无人工权限或强制放行入口。PASS 仅代表已执行的确定性检查通过，不等于法律意见、人工验收或已发布。

## 板块与知识库边界

工作流与工具在三板块共用，法源、案例、模板按任务包的 board 独立绑定。所有 library.search/read/manage/update、templates.list 必须传入该 board；同名条目在不同板块仍是独立记录，不使用 market=neeq 或 common 合并池。更新只作用于指定板块；不得用其他板块的资料或旧任务快照补齐缺口。

初始拆分保留重叠资料；收录范围不等于逐条适用性已核对。基础层、创新层案例的发布时层级尚待核实。创业板 imported_source_unverified 案例缺少可核验官方原件，只能作为待核验线索，不得用于已核实实践断言或法律依据；模板与导入版式保持待复核状态，不能把历史标签或机械通过当成专业验收。
