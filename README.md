# NERO Disclosure

面向信披工作的本机 AI 工作台，支持信披咨询、公告起草、Word 制作，以及法规、案例、模板和公司历史公告管理。当前开放创业板。

**源码公开，仅限学习、研究和非商业用途，禁止商用。**

## 下载后能做什么

本仓库包含软件源码、开发脚本和虚构样例，不包含正式知识库、公司历史公告、个人业务记录、模型账号或安装包。安装依赖后可以启动开发工作台；用于真实业务还需要配置自己的模型账号，并加载有效知识包、模板与所需公司公告。

## 安装与启动

环境：macOS、Python 3.13、Node.js 22.19 或更新版本。以下命令在终端执行：

```sh
git clone https://github.com/cyanask/NERO-Disclosure.git
cd NERO-Disclosure
python3.13 -m venv .venv
.venv/bin/python -m pip install -r 01_app/requirements.lock.txt
(cd 01_app/runtime/pi && npm ci)
(cd 01_app/frontend && npm ci && npm run build)
.venv/bin/python 01_app/scripts/dev_server.py
```

打开 [http://127.0.0.1:8765](http://127.0.0.1:8765)。开发入口预置“虚构审查公司”，可直接浏览工作台；按 Ctrl+C 停止服务。端口被占用时可添加 `--port 8878`，不要直接关闭未知进程。

开发入口首次建立样例目录，再次启动保留修改；遇到没有有效样例标记的既有知识目录会停止。样例只用于开发，不可作为真实法规、案例或公告使用。

## 配置模型

在“模型设置”中选择供应商，保存自己的 API Key 或按页面完成 OAuth 授权，启用模型并测试连接。兼容接口需填写实际 API 类型、端点和模型 ID；会话开始后保持本轮已选模型，失败不会自动切换供应商。

API Key 和 OAuth 凭据由系统凭据库管理，换电脑或工作区后重新授权。连接测试、咨询、生成和联网功能会使用对应账号的服务额度。

## 使用

- 在对话操作台提出咨询需求；要求“拟公告”时准备正文，明确要求 Word 时生成文件。
- 内容不足时先核对缺项；明确接受已告知缺口后可生成待补工作稿，事实冲突仍需处理。
- 在知识库页面维护法规、案例和模板，在“公告时间表”管理本公司历史公告。
- 在文档区或“交付文件”下载 Word。修改已登记稿件会保存新版本；网页文字预览不能代替实际 Word/WPS 版式检查。
- 查看“执行记录”和“工作进展”了解本轮操作，必要时停止执行。文件保存不等于正文确认或公开披露。

当前流程不接收新的人工稿回传；历史文稿和版本仍可读取。正式公司身份核实及模型业务功能需自己的模型授权。

## 知识包与数据

```text
01_app/          软件、运行方法、脚本与测试
02_knowledge/    正式知识包与公司公告，不提交 Git
03_local/        本机事项、会话、文稿与配置，不提交 Git
```

正式环境请使用独立克隆，在 `02_knowledge/` 放入经授权的完整知识包（含 `packages/index.json`），从仓库根目录执行：

```sh
.venv/bin/python 01_app/scripts/refresh_knowledge_packages.py --verify
.venv/bin/python 01_app/scripts/run.py
```

不要用正式资料覆盖样例目录后继续运行开发入口。知识包、模板及公告的获取与接纳需要自行完成，上述命令不会下载或补齐业务资料。

常规源码入口把数据库和模型配置写入 `03_local/var`；开发入口使用 `03_local/dev/var`。两者的文稿与附件仍位于同一克隆的 `03_local/work/`。迁移前退出服务，完整备份并复制知识目录和本机目录，不能只复制数据库文件。
